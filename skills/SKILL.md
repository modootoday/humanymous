# Operate Humanymous

Help an operator make a bounded, reviewable change to their own deployment.
Confirm the installed artifact/version and supported OS/architecture from its
manifest and available qualification receipt. Repository source or a successful
build alone does not establish installed runtime support. Do not invent CLI
commands, a package-registry release or a supported framework/ABI tuple.

Choose the relevant procedure; read only that reference first:

- Install or plan a signed service upgrade: [installation](references/installation.md).
- Diagnose readiness, restart/rollback needs or an authority failure: [operations](references/operations.md).
- Connect a Node/Bun framework or nginx module: [adapters](references/adapters.md).
- Interpret receipts, missing evidence or an unsupported feature: [qualification](references/qualification.md).

Default to inspection and a concrete plan before mutation. Use existing user
authorization; ask only for missing deployment identity, artifact trust or a
consequential action that has not been authorized. Never request a private key,
unseal passphrase, bearer credential, cookie or personal browser profile in chat.
Use the deployment's provisioned private-input/credential mechanism. Do not
invent one or put secrets in command arguments, environment or plaintext files.

Preserve fail-closed enforcement and required evidence. Do not change detection
weights, thresholds, hard rules or verdict bands as a troubleshooting shortcut.
Erasure, kill switch and permanent bans require the deployment's dual-control
workflow. Pass/CHALLENGE must retain keyboard/screen-reader access and cannot
require motor richness or speed. A browser or accessibility tool is not proof of
automation; the reference system intentionally has a T4 detection ceiling.

Report what was inspected, planned, changed and actually verified separately.
Keep unsupported, skipped, mock/synthetic, policy-denied and missing evidence
visible. Do not retry a blocked action through an alternate tool or disable a
sandbox. Release/tag/registry publication and arbitrary external infrastructure
are separate tasks requiring their own explicit scope.
