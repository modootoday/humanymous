# Interpret support and verification

Keep these facts separate: artifact available; source compiled; pure unit checked;
actual process/native fixture executed; authenticated peer exercised; complete
product/browser/human/AT path qualified. A green result proves only its measured
source and denominator. New source requires new evidence.

Record exact source/dirty manifest, artifact hashes, OS/architecture, runtime and
framework versions, test counts, failures, ignored/unsupported cases, effect
counts and raw-evidence availability. Missing receipts or required signals fail
closed. A sample response, regex routing proxy or self-reported skill name is
not authenticated provenance, real model activation or full product success.

The reference Node qualification receipt is
`humanymous.node-native-qualification/1`, with source/package/provenance hashes,
host runs, authority-Docker results and advertised tuples. No tuple is qualified
merely because it appears in build targets. `full_native_qualified` must be backed
by actual source-bound runs; it is not a flag to set manually.

A standard hosted runner label does not establish interactive screen-reader,
IME, physical device, GPU/DPI or independent-organization witness qualification.
Obtain direct evidence in an appropriate environment for such claims. A sandbox
rejection is not permission for `--no-sandbox` or an alternate access route.

This skill guides installation/operation and adapter decisions. It does not
publish releases, create paid infrastructure, change scoring or certify the
deployment. Internal development rules belong in the repository's separate
developer catalog, not in this product skill.
