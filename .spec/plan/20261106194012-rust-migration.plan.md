### Authenticated WAL recovery checkpoint — 2026-11-07

Storage now exposes verify_history / Wal::verified_history, reusing the existing
canonical/HMAC/signature/Merkle verifier rather than duplicating cryptography.
Recovery requires a nonempty expected node and HMAC key, trusted writer public
key, exact node ownership of all records/checkpoints, strictly increasing
nonzero checkpoint sizes and complete lowercase Merkle commitments. Optional
independently protected trusted head must be present exactly; optional witness
policy requires witnessed checkpoints rather than accepting empty coverage.
Empty storage requires explicit first-install permission and cannot coexist with
a trusted anchor. VerifiedHistory fields are private so parsed bytes cannot be
mistaken for authenticated state through direct construction.
Rollback resistance extends through independently retained anchors only; this
API does not establish external head persistence or prevent deletion of a later
unanchored tail. Disk writer lock is retained during consistent snapshot checks.
