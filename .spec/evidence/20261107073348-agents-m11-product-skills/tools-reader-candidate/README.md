## Concrete contract and bounded read

example-request.json contains the exact original source/preservation paths,
lengths and SHA256 values at base, plus an explicit absolute repo root. It does
not contain their mutable contents. Its old-source hashes will refuse a changed
checkout; do not rewrite them silently or interpret the example as current proof.
schema, operation, repo_root, source_commit, source and preservation are required;
each input requires path, owner, presence=required, bytes and lowercase SHA256.
Unknown/duplicate fields, optional/live mode, wrong operation, malformed commit,
traversal, wildcard, alias/case collision and oversized entries are rejected.
The commit and owner remain caller declarations, not authenticated authority.

There are exactly two selected files. Each input and request is at most2MiB;
actual command reads are at most3*(2MiB+1), including existing EOF probes. This
is stricter than5000files/64roots/2GiB/512MiB ceilings, never a scan authorization.
All three captures share one original SystemClock and30s cooperative deadline.
selected_inputs::capture_request_file is reused directly: no new reader framework,
generic wrapper, directory discovery or copied filesystem implementation.
The request must be absolute before that helper can resolve a relative path.
Source and preservation are absolute root+validated relative selections only.

Existing capture checks each ancestor and Windows reparse flags, regular-file
kind, metadata length/time before/open/after, actual bytes and probe limits. It
returns the captured bytes; those exact bytes are hashed and then parsed without
reopening or LF normalization. Missing/link/changed/cap failures return sanitized
phase+error codes. Manifest length/hash mismatch or invalid UTF-8/JSON refuses.
Preservation is limited to4096 records; a source-specific stale line hash refuses.
The existing language report still records malformed preservation and new prose
debt, never English conformance. Historical source/preservation bytes stay intact.
